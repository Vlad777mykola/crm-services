# Route Inventory

Generated by enumerating every route registered in `backend/src/modules/**/*.routes.ts`
and cross-checking against `contracts/openapi.yaml`. This is the source of truth for
what exists **today**. Any endpoint that appears in a migration-plan phase but not in
this table is **new functionality** and must not be built without explicit approval
(see `microservices-extraction-checklist.md`, Task 0.0 hard rule).

Router mount order in `backend/src/app.ts`: health, auth, users, companies,
company-members, specialists, company-specialists, services, service-specialists,
appointments, notifications, reviews, dashboard.

## Health

| Method | Path | Module | Handler | Target service | Phase | Status |
|---|---|---|---|---|---|---|
| GET | `/health` | health | `health.routes.ts` | n/a (legacy diagnostic) | - | legacy |
| GET | `/health/live` | health | `health.routes.ts` | every extracted service (own copy) | every phase | legacy |
| GET | `/health/ready` | health | `health.routes.ts` | every extracted service (own copy) | every phase | legacy |

Note: `/health/live` and `/health/ready` are not domain routes — every extracted
service gets its own copy of these two endpoints (already the pattern used by
`outbox-publisher`, `notifications-service`, `metrics-service`,
`backend-projection-service`, `ai-service`). They are not "routed" by the gateway to
a single owner; the gateway/each Ingress rule points at whichever service it fronts.
